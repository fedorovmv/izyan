# Безопасность

- Главный инвариант: никогда не выводи «не эксплуатируется» из
  отсутствия находки. Негативный результат требует falsifier +
  negative verification.
- Не ослабляй консерватизм ради «красивого» результата: новые
  эвристики могут только сужать доказанное, не расширять выводы.
- Exec-инструменты (`run_build`, `run_tests`, remediation apply) —
  только за явным флагом (`--allow-exec`/`--apply`); по умолчанию —
  сухой режим и честный limitation.
- Секреты и приватные пути не коммитятся: env-файлы в `.gitignore`,
  продукт-репо — `${VA_PRODUCT_REPO}`.
- Валидация входа: advisory JSON, ticket JSON, corpus JSON —
  нечитаемое входное → error/limitation, не паника и не молчаливое
  угадывание.
- LLM-промпты не содержат секретов; tool-аргументы валидируются
  (argIndex ≥0, пути внутри разрешённого скоупа — module cache +
  product tree).
