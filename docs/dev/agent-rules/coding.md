# Написание и изменение кода

- Стиль существующего кода: компактно, без лишней вложенности, общие
  абстракции переиспользуются. Не добавляй комментарии, если не
  просили; если удалили случайно — верни.
- Зависимости: проверь, что библиотека уже в `go.mod`, до использования;
  новые — через `go get`, не ручной правкой.
- Обработка ошибок на правильной границе: не оборачивай каждую строку
  в try/collect-error; смотри, как соседний код собирает/пробрасывает
  ошибки.
- Публичная поверхность минимальна: unexported по умолчанию, exported
  только для осознанной точки интеграции.
- Имена по домену: `Condition`, `Claim`, `Evidence`, `DataFlow`,
  `Validation` — не плоди синонимы для тех же понятий.
- Никакого отладочного вывода в коммит; артефакты (`md`, `out`,
  бинари) не в репо.
