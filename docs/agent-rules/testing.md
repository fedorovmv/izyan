# Тесты

- Каждое новое правило/эвристика — регрессионный тест. Фикстуры —
  мини-репозитории `testdata/<name>prod` со своим `go.mod` и dep-
  пакетом (`example.com/dep` и т.п.).
- Покрывай границы: negative-кейсы так же важны, как positive
  (напр., односторонняя граница ≠ гарда — `onesidedprod`;
  address-taken ≠ покрытие — `addrtakenprod`).
- Тесты на семантику, не на форму: проверяй результат claim/verdict,
  не текст совпадения где возможно.
- Полный прогон перед завершением: `go test ./...`.
  Для финальной проверки анализатора используй автономный бенчмарк:
  `go run ./cmd/izyan eval --corpus eval/corpus-real.json -j 4`
  (базовый уровень: 20/38 cleared, строго `false-safe=0`).
  Интеграционный live-корпус:
  `VA_PRODUCT_REPO=<r> go run ./cmd/izyan eval --corpus eval/live-corpus.json`
  (цель 11/11, `false-safe=0`).
- **Экономия времени тестирования (запрет преждевременного полного эвала):**
  - На промежуточных шагах (TDD, микро-таски Task 1..N-1, исправление замечаний ревьюера) запускай **ТОЛЬКО** быстрые точечные юнит-тесты (`go test -run <Name> ./...` — секунды).
  - Если требуется проверить поведение анализатора на кейсе из корпуса — использовать **строго точечный запуск** через флаг `--case <id>`: `go run ./cmd/izyan eval --corpus eval/corpus-real.json --case <id>`.
  - Полный прогон корпусов (`eval/corpus-real.json` и `eval/live-corpus.json`) запускается **СТРОГО ОДИН РАЗ** — на этапе финальной валидации всей ветки/фичи перед сдачей работы.
- Флаки недопустимы: LLM-недетерминизм в тестах отсекается
  (`--deterministic-only`, стабы `StaticSource`/manual root causes).
